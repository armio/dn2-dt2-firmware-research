# R020 candidate and accumulated sampler fixes — November 6, 2026

**R020 is the current candidate; R012 remains stable.** R020 includes the work
developed through R015–R019 and a focused guard for SLICE-grid restoration at
startup. The owner confirmed R020 opens normally and retains stock audio and a
saved 16-slice grid after switching power off and on with USB disconnected.
This is a targeted cold-boot observation, not an overall stability designation.

The [browser patcher](../browser.md) and [native builder](../../README.md#build)
produce firmware locally from the owner's official **DN2 OS 1.11** and
**DT2 OS 1.16** files. No factory samples, private sample bank or prebuilt custom
firmware are required. This repository publishes source and evidence summaries,
not firmware, private projects, samples, disassemblies or raw device captures.
Output identities and release status are pinned in the
[R020 manifest](../../releases/r020.json).

### Editing and MIDI controls

All six sampler Machines use DN2 **CC 40–47** and **NRPN MSB 1 / LSB 73–80** for
their eight SYN controls. Both SYN views use the same mapping. Empty controls
ignore messages, and stock Machine mappings remain unchanged.

**SAMP CC 43** selects within the current project bank. **NRPN 1:76** selects
absolute project position 0–1023, carrying bank and slot together. Invalid
positions are rejected. Outgoing CC reports the slot within its bank.

Mixed held-trig edits apply the addressed Machine's parameter definition to
each target. Sample randomization chooses occupied project slots; an empty pool
preserves the selection. TUNE and LEV retain the donor's randomization exclusions.
The minimum accepted newly split slice is 144 frames; rejecting a split leaves
the previous endpoints intact.

### Sample loading and rendering

Replacement audio is staged before the old allocation is released. Invalid
input, late file errors and insufficient staging RAM preserve the original slot.
Slots that share PCM retain separate display names. A transport timeout still
requires restart: retained host data cannot prove which descriptor an
interrupted DSP link received.

For all six sampler Machines, shrinking a sample beneath a held voice stops
that old voice; a new trigger plays the replacement. Equal-size and growing
bindings retain their behavior. The SLICE bounds fix covers NOTE selection
below C1, markers recalled against a shorter sample and reverse interpolation
at the final frame.

STRETCH previously corrected the second grain's position by only one sample
length. Very short samples could therefore cause reads outside the allocation.
The correction reduces that offset modulo sample length while retaining its
fractional position. Native-instruction tests with poisoned surrounding memory
now make zero out-of-allocation reads in the covered cases; ordinary long-sample
output remains byte-identical. This finding concerns the ported runtime; it is
not evidence that stock DT2 firmware has the same fault.

### SLICE-grid storage

The native DN2 Sound codec stores 359 bytes and omits the ported 772-byte slice
map. R019 introduced immutable `/.slc_<content key>` files on +Drive and a small
key that survives the unchanged native codec. R020 retains this mechanism.
Save the project after creating or editing a grid.

**Native Sound/project exports contain the key, not the companion file.** They
are not complete backups of slice edits. Moving to another DN2 or restoring
after formatting sample storage needs the companions too. Automatic bundling
and restoration are not implemented. Previously discarded grids cannot be
recovered from an old native Sound/project alone.

Failed new-file writes remove only files created by that attempt, allowing a
retry without deleting a pre-existing invalid or colliding object. Aggregate
project saves propagate grid-save failures. Deferred restoration covers active
Sounds and Sound-pool records, with at most one unresolved pool grid per UI poll.
This does not make saves atomic under power loss.

## Cold-start failure and R020 guard

An R019 owner reported a black screen after the splash following power removal.
A normal power-switch reboot with USB disconnected also failed. The bootloader
remained accessible; recovery to R012 restored normal UI and stock audio. No
fault-state capture was available, so the precise hardware failure could not
be established from the device.

The investigation reproduced a startup defect in R019's native Sound path.
SLICE deserialization can request companion files before the UI task initializes
the sample filesystem. Its mounted flag, `0x46B9608C`, lies in private BSS that
is cleared during that later initialization. R019 accepted any nonzero value,
including stale DDR contents. Earlier cold-project fixtures explicitly set
this flag to zero and therefore missed the case.

R020 first checks the startup status at `0x47A9CD7C`, initialized by the runtime
copy. Companion allocation and access require **startup status 2** and
**mounted flag exactly 1**. Other states preserve the key and defer work to the
existing UI poll. The interrupt-mask guard remains intact. The change appends
52 bytes and replaces a 12-byte ColdFire gate; DSP, buffer ownership, control-frame
ordering and protected firmware sections remain unchanged from R019.

The owner installed R020, loaded the saved slice project and confirmed a normal
power-switch cycle with USB disconnected retained normal UI, stock audio and
the 16-slice grid. This addresses the failing workflow in that observation;
there was no instrumented post-boot readback. The missing guard is confirmed in
native instruction tests, but attributing the original black screen solely to
it remains an inference.

## Validation and its limits

### Public build reproduction

On November 6, a fresh command-line build rebuilt every required MAIN and DSP
stage from the two official OS files and generated silence. Its MAIN, expanded
MAIN, runtime, DSP and final SysEx matched the pinned R020 identities. The
browser backend and the actual browser Worker/download independently produced
the same **2,570,912-byte** output:

```text
77528d1c65f8101a597beccd4e619a0bcc3fe18a56147de1ddbf4b8b1e238413
```

All 41 public unit tests, six Python browser-recipe tests and the JavaScript
recipe boundary tests passed. Independent publication review checked source and
adapter provenance and exclusion of private data. Native SHARC replay bytes are
copied from the user's derived DSP input; they are not embedded in the published
adapters. Test firmware and private build evidence remain outside the repository.
Exact reproduction verifies the published build path, not hardware reliability.

### Offline combined cases

The research executes native ColdFire/SHARC instructions with explicit boundary
fixtures. These results are not a claim of exhaustive DT2-manual compliance.

- **Controls and allocation:** mixed-Machine locks, Control All and restore,
  all six sampler MIDI mappings, dynamic/reuse/reserved/unison configurations,
  and synth/sample steals in both directions. The allocation state matches the
  stock oracle for 192 combinations of 110 allocation/release events. Actual
  envelope timing and scheduler behavior remain hardware questions.
- **Connected sequencing and DSP:** native step production, Sound locks,
  parameter locks, smoothing, modulation, serialization and DSP consumption
  are linked by exact control frames. Six sampler renderers produce output;
  combined cases change parameters during Sound replacement and deliver STOP
  releases. UI notification queues and the master-effects trailer are outside
  this fixture.
- **Modulation and effects:** all six samplers, seven LFO waveforms/five modes,
  pitch and incoming MIDI edits; stereo filter/insert/pan/level behavior; bounded
  delay, chorus, reverb and compressor runs. Cross-send sums are composed by
  the test host, so complete physical routing is not qualified.
- **Storage and Recorder:** normalization, mono/stereo trim/save, fresh sample
  filesystem mount, download/retry, rename, shared-slot replacement failures and
  project identity restoration. Physical input acquisition, sector media,
  RTOS synchronization and DSP upload are declared fixture boundaries.
- **Project persistence:** the native full-project codecs retain 10,240 locks,
  128 pool Sounds, 12 populated grids and 127 bank-H identities. A fresh-state
  re-save is byte-identical. Failure cases cover malformed/missing companions,
  rejected headers, short writes, close errors, explicit clear and delayed mount.
- **R020 readiness regression:** eight startup/mount combinations include
  unstarted, mounting, failed and invalid nonzero readiness. Disallowed states
  perform no companion allocation or file I/O; later ready polls restore all
  grid bytes. A focused fresh full-project decode with poisoned readiness retains
  active and pool keys, then restores both after mount. Its 12,890,116-byte
  re-save is identical. Deferred aggregate saves fail without file I/O and
  succeed on a ready retry.
- **Package and startup:** section integrity, protected-region checks and both
  native loader staging paths preserve the intended runtime, registers, stack
  and boot flags. These execute early loader code, not the entire hardware boot.

The manual coverage ledger reviewed 243 overlapping entries from the DT2 OS
1.15A manual; the actual donor remains OS 1.16. Entry counts are not a completion
percentage. The latest SHARC audit reports no new errors or memory declaration
conflicts, with inherited review findings still open. It does not establish
hardware DSP deadline margin.

### Emulator limitations

The pinned ColdFire emulator required byte-verified EMAC instruction corrections
to model fractional smoothing and operand ordering. Those corrections change
the fixture, not the device firmware. Independent recurrence checks retain
stable controls across all 1,734 words and convergence runs.

The pinned SHARC runner has an unresolved odd-voice SIMD byte-store cleanup
limitation. Correctly received OFF masks therefore do not establish bounded
release for those voices. Mixed stock-synth transitions are covered at the
control/dispatch level, not as complete acoustic validation.

## Practical upgrade notes

1. Build R020 from the two required official OS files and install with Transfer.
   Keep private backups and a known-good recovery OS.
2. Leave working sample storage intact. For first installation with unavailable
   storage, follow [FORMAT SAMPLES step by step](../samples.md#sample-storage-setup).
   It erases samples, grid companions and other mods' data in that area. It is
   separate from stock FORMAT +DRIVE and reset commands.
3. Upload samples, wait for completion, then load them into the project and
   assign them. **Save the project after assignments or slice edits.**
4. Finish saves, loading and transfers before switching off. R020 defers early
   startup reads; it does not guarantee recovery from writes interrupted by
   power removal.
5. Stop playback during bulk uploads/restores. Stutters, missed notes or silence
   during heavy transfers have been observed. Resume after transfer completion;
   report problems that persist afterward.

The DN2 contains the physical flash capacity; stock firmware does not expose
this area as sample storage. The tested sample filesystem reports about 20 GB
in Transfer. A zero-capacity display does not prove the area is empty and is not
permission to erase existing data.

## Remaining work

The intermittent internal-audio-track hung note remains unresolved. The external
MIDI expiry fix and bounded MIDI playback test do not establish its cause.
Physical MIDI/live recording, some combined Control All/held-trig/browser cases,
complete preset-pool/naming workflows, quantization and song editing gestures,
full physical routing, prolonged USB load and storage fault endurance remain
incomplete. An earlier physical-input-channel spike observation also lacks a
matched isolation capture.

R020 is not presented as a fix for every USB or sequencing report. Exact
end-to-end USB latency, sustained DSP headroom and repeated project-change
endurance still need measurement. See [USB research](../usb-research.md),
[Recorder](../recorder.md) and [publication boundaries](../publication.md).
