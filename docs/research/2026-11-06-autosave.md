# R022: working-state samples and SYN sample menu

**R022 is a candidate; R012 remains stable.** R022 includes R021's SYN-view
repair and fixes incremental sample-pool autosave. Both defects were reproduced
in native-code replay. R021/R022 hardware confirmation remains pending. The
reported iPhone USB freeze remains unresolved.

The [browser patcher](../browser.md) and [native builder](../../README.md#build)
produce R022 from the two official OS inputs. No firmware, samples, private
projects or raw device captures accompany this report. Output identities are in
the [R022 manifest](../../releases/r022.json). Earlier R020 cold-boot observations
remain documented in the [preceding report](2026-11-06.md); they are not R022
hardware results.

## Working-state backup missed sample identities

The reported symptom was a missing project sample pool after reboot, without an
explicit project save. That does not establish deletion of +Drive audio files.
Working-state recovery at boot and an explicitly saved project are separate
paths; SAVE PROJECT should not be required solely to retain the active sample
pool through a normal reboot. A freeze can still prevent pending work from
completing.

On the DN2 OS 1.11 layout, whole-project serialization at `0x400E1494` already
updates the port's companion sample table. Ordinary ProjectSettings changes use
a different path: worker `0x400469E2` calls serializer `0x400DF57A` at
`0x400469FE`. That worker updates native settings, but the previous port did not
refresh its sample companion. Native donor sample load/unload emits the
ordinary settings notification, so the live pool could change while the
working backup retained old identities.

Native working backups alternate between sectors `0x40000` and `0x48000`;
they are distinct from explicit saved-project slots. The existing power-off
adapter copies the prepared mirror companion into its final block. It was
therefore persisting the stale table supplied to it.

R022 hooks only the settings-worker callsite. Under the existing recursive
project lock, it calls the original serializer once, then refreshes the working
sample companion. Guards require a successful native result, the exact working
destination and current raw settings source, valid active ownership, and
matching raw/active/mirror project UIDs. Explicit saved-project companions are
untouched.

Identical sample identities skip the 16 KiB record copy and CRC. Recorder
preferences occupy a separate 24-byte record within the existing header; the
helper compares a stack-prepared record before updating it. Identical samples
and preferences cause no companion writes. The native queue mutex is released
before the worker runs, avoiding an added queue/project lock inversion.

The added helper is 376 bytes at `0x47ACEE98` in this exact build. There is no
new allocation, storage I/O, audio-callback work or shutdown-handler work.

## Stock-to-sampler switches could retain the old SYN view

The owner reported that turning D after selecting ONESHOT did not open the
sample menu. Earlier replays explicitly reselected SYN before turning D, which
masked the missing transition.

The port has separate stock and sampler SYN views. Native Machine assignment
updates the Sound but reselects the page only when audio/MIDI classification
changes. A stock synth and a sampler are both audio Machines. Generic Project,
ActiveTrack and Sound notifications redraw the old view rather than replacing
it, so the first D turn can reach the stock handler instead of the sample list.

R021 adds deferred reconciliation after the existing UI poll. It uses the
existing Source factory and native selector only when the exposed SYN view no
longer matches the Machine. It defers for modal dialogs, pending cleanup,
selected-trig editing, construction, expired ownership and non-SYN pages.
Stable matching views do not get reselected. R022 retains this change.

## Evidence and limits

| Check | Result and boundary |
| --- | --- |
| R020 autosave baseline | Native sample load and settings worker leave the new slot empty in the working mirror and power-off block; a fresh emulator restores the empty slot. |
| R022 working backup | Load → native settings worker → prepared power-off block → fresh emulator restores the identity. Unload removes it. The explicit saved cache remains unchanged. |
| Autosave guards | Eight owner, UID, destination and native-failure cases preserve the prior companion. Unchanged identities skip rebuilding; Recorder-only changes update their own header. |
| SYN routing | All six sampler entries, reverse switches and unchanged-family transitions pass: ten transitions, nine guard cases and 37 polls with the previous poll called exactly once. |
| Startup and package | Both native loader staging paths pass unpacking, memory-copy, BSS, stack, register and boot-flag checks. Package integrity and transport round-trip checks pass. |

Autosave replay fixtures cover PCM acquisition, job scheduling, backup selection
and bulk boot conversion. Native load/unload, settings construction,
notification, worker, serializer, recursive lock, companion CRC and backup
restore execute. UI fixtures cover Project/Track accessors, event fanout and the
preceding filesystem poll; assignment, subscriber callbacks, page selection,
encoder handling and popup ownership execute natively.

These tests do not establish physical reboot endurance, scheduler timing or
recovery from the reported freeze. Power-off can interrupt a companion update;
the existing invalid marker rejects torn state but does not make recovery
atomic. R022 cannot reconstruct assignments already lost from a backup. DSP,
USB buffer ownership and control-frame ordering are unchanged from R020.

## Targeted hardware checks

1. Load a sample into the project and wait for loading to finish. Without SAVE
   PROJECT, use the power switch to turn off and on. Verify the sample remains
   in the project pool and plays. This checks working-state recovery; explicitly
   loading a saved project intentionally restores its saved checkpoint instead.
2. Switch a stock synth track to ONESHOT and turn D on SYN without first leaving
   the page. Verify the sample list opens. Switch back and check stock controls
   and audio.

Allow saves, loading and transfers to finish before shutdown. Do not use abrupt
power removal or a forced freeze as a substitute for either check.
