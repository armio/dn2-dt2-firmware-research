# Faust Oberheim kernel for DN2

Research port; no hardware qualification or cycle-budget claim.

`sem_filter.c` adapts Eric Tarr's `ve.oberheim` state-variable filter and Julius O. Smith III's cubic soft clipping. The signal recurrence is retained; this is a SEM-family virtual-analog model, not a measured emulation of a particular physical unit.

Sources:

- [Faust vaeffects.lib](https://github.com/grame-cncm/faustlibraries/blob/b0e363a602a48eaced21e3838ba3f742dfd54c94/vaeffects.lib), `oberheim`, licensed LicenseRef-STK-4.3.
- [Generated scalar reference](https://github.com/SpotlightKid/faustfilters/blob/00cb332796b57487e5e0f384cb624345ca938561/plugins/oberheim/Oberheim.cpp), by Christopher Arndt; corresponding header and wrapper license retained unchanged in `reference/`.
- Exact upstream STK notice is in `LICENSE-STK-4.3.md`; preserve these notices with copies.

One `SemFilter` belongs to one voice/channel. The kernel never allocates. Reset clears both integrators and settles controls to targets, for explicit voice lifecycle use. Ordinary control changes retain audio history. `sem_filter_set` accepts cutoff in Hz, Q 0.5–10, LP/notch/HP morph 0–1 and a bandpass override. Morph midpoint sums LP and HP, matching the upstream notch output. Mode changes crossfade through smoothed output weights.

The upstream generated wrapper smooths Hz and computes tangent every sample. This adapter computes tangent only in the control setter and smooths the prewarped coefficient `g`, inverse Q and output weights using the same 44.1/sample-rate coefficient. Consequently steady-control audio matches the upstream recurrence; modulation trajectories are deliberately different. `sem_filter_set_coefficients` lets a native adapter supply its own prewarped cutoff without libm in the audio loop. No approximation table is introduced.

Define `SEM_FILTER_NO_LIBM` to omit the Hz setter and math dependency entirely. Initialization uses a normalized cutoff equivalent to 1 kHz at 48 kHz; the adapter supplies its desired coefficient before playback.

The C block processor retains integrators/control values in locals, expands the five fixed smoothing updates and shares the denominator reciprocal. It remains the host reference. The R024 SHARC build replaces only that compiler-generated function with `sem_filter_process.asm`: register-resident histories and controls, DAG sample access and a hardware loop. The wrapper, coefficient conversion and state layout remain C. The scalar tick provides another comparison path.

The assembly retains the same multiply/add order, reciprocal seed with two Newton refinements and final residual correction, cubic clipping, input bounds and state recovery. It bypasses coefficient smoothing only when evaluating the rounded next-step recurrence for **all five controls** yields their current bit patterns. These fixed points would remain unchanged throughout the block. This is not an epsilon test, elapsed-time cutoff or tail gate: integrators and every sample still run. Moving controls continue smoothing every sample. No voices are capped, tails truncated or sample blocks omitted.

Public control setters replace nonfinite values with safe defaults and bound cutoff below Nyquist. The processing boundary bounds input to ±16 and recovers from nonfinite/implausible integrator state. IEEE-754 exponent and unsigned magnitude checks are explicit: the pinned selcc compiler's SHARC comparison lowering did not preserve C unordered-NaN behavior in the original guards. Host and emitted-code tests cover NaN and both infinities. Compile without fast-math. Native integration must initialize the object before processing and keep unrelated code from writing its state.

`sem_dn2.c` adapts native DN2 control values using the stock MULTIMODE cutoff table, including linear interpolation after native keytracking/envelope/modulation. Its coefficient range is capped at `g = 6.3137515`, corresponding to 21.6 kHz at 48 kHz. The stock table reaches 22 kHz; its highest entries therefore flatten at this cap. This is an intentional below-Nyquist bound, distinct from the standalone Hz setter's 20 kHz cap. Native RESO 0–127 maps to Q 0.5–10. Mode values 0/63/126 are LP/notch/HP; 127 selects BP. Each 128-byte native slot owns its filter history and controls. Clearing its active marker resets history on next use; ordinary control changes preserve history. Blocks longer than 32 samples are rejected without modifying audio or state.

Host validation: `python3 scripts/check_sem_filter_host.py --out <directory>`. Tests compile the unchanged upstream C++ reference alongside the C port, compare all four steady-control responses, and exercise modulation, hot input, state reset, block boundaries and independent stereo histories. SHARC compilation/emulation and full-polyphony cost are separate gates.

Linked SHARC validation: `python3 scripts/check_dn2_sem_kernel.py <kernel-folder>` after `build_dn2_sem_kernel.py`. It executes producer-delimited instructions, compares emitted-code audio/state with the host build and gates every DM access to the active channel state, exact audio buffer, bounded stack or native cutoff table. Wrapper cases cover modes 0/63/126/127, RESO 0/127/128, interpolation and table endpoints, two independent slots, first-use/reset behavior, oversized-block guards and nonfinite controls/audio/history. Native wrapper host tests substitute only the absolute cutoff-table address; table bytes come from the loaded native DSP.

R024 linked kernel `b55266440e4e3f11511e8a274a2e8340feaa20a2774d5a6a7332393a230b1a1b` passed 1,051 producer instruction boundaries and 6,313 checked stores with a maximum 288-byte observed stack footprint. The equivalent R023 suite executed 27,713 stores. The 32-sample recurrence now takes 1,755 emulated instructions with settled controls and 2,370 while controls move, compared with R023's 5,390: 3.07× and 2.27× reductions respectively. The native C wrapper takes 2,185–2,216 on warm slots and 2,744–2,775 on first use. These counts exclude the external adapter and do not establish hardware cycle savings.

The R024 DSP image hash is `b5ba74131db8ec13250950296a21326b589971d8b7da5c54144f1b1be3564c29`. Its adapter saves the 34 registers/status words covered by the decoded clobber audit, while tests still require all 99 incoming native registers/status values to survive. R8–R15 and the assembly's additional I0/M0/L0 usage are also checked at the C boundary. Both builds use explicit 48-bit instructions and explicit return-frame operations. The adapter sets RND32 (MODE1 bit 16), clears TRUNC (bit 15) and disables SIMD for the scalar call, then restores the caller's original context. Bit 24 is circular-buffer enable, not the float-rounding control.

`scripts/check_dn2_sem_performance.py --candidate <build-folder> --out <report.json>` is a hard regression gate. It executes settled audio, moving controls, exact silence and nonzero tails at all 32 independent voice/channel state addresses, requiring host-equivalent audio/state and no neighboring-state writes. Limits are 1,800 linked instructions per 32 samples for settled/silence/tail cases and 2,500 for moving controls. The unsafe R023 kernel must fail the same limits; R024 passes. The report binds both candidate DSP and kernel hashes. These are regression limits derived from the observed unsafe implementation, not a conversion to DSP percentages or a real-time scheduling guarantee.

The focused kick regression (`check_dn2_sem_kick_sweep.py kernel --build <build-folder> --out <directory>`) runs three 512-block sweeps/retrigger cases through emitted instructions. At the reported 36.418 Hz cutoff and Q 4.165 or 10, R024 retains the same maximum differences as R023: 2.38e-7 output and 2.63e-7 state versus host, with zero guard faults. The 341 ms runs exceed 14 smoothing time constants and preserve all tails. The low-cutoff distortion reported on R023 was not reproduced numerically; live R023 profiling separately confirmed render deadline overruns.

`scripts/check_dn2_sem_load.py` compares native render paths at 1/4/8/16 requested voices. Historical R023 stereo-sampler cases added 10,775 / 42,668 / 85,192 / 170,240 emulated instructions per held 32-sample frame over native MULTIMODE, with both channel filter calls observed for every requested voice. R023 kernel identity was `0e30a076ac4f5ef589238a73f129eac003e0f91362cb44ae121921ff3a020285`; those costs are not current R024 results. These counts do not establish silicon cycles, worst-case system load, full-polyphony viability or a hardware timing budget. The pinned native byte-event emulator can leave odd voice outputs silent; those filter calls still execute on silent input. Mono-carrier cases inject synthetic audio after the Wavetone oscillator and therefore establish filter work, not stock oscillator acoustics or cost. RTOS/interrupt/cache/DMA/USB timing and simultaneous audible 16-voice operation remain hardware checks. The 288-byte C stack observation does not bound nested interrupt stack usage inside the separate 8 KB reservation.

The final R024 16-voice subset observes all 32 channel calls. Its held native frame takes 197,687 instructions for stereo samples and 319,378 for the mono-carrier fixture. Historical R023 equivalents took 318,167 and 439,858 respectively: reductions of about 37.9% and 27.4% in these bounded fixtures. The R024 SEM overhead over native MULTIMODE is 49,616 instructions in either case. These figures include native processing and the reduced adapter save, while retaining the fixture limitations above.

The coefficient wrapper still uses the pinned C compiler. Its stack traffic is outside the sample loop. Any further optimization must retain reference equivalence, state isolation, C/native register contracts and the instruction-cost gate; offline acceptance still requires hardware timing and audio verification before claiming a stable release.
